# E2E + agent-driven QA (proposal)

Status: **proposal, not started** · 2026-10-21

## Goal

Get to the point where a PR can be trusted to merge **without a human clicking
through the preview**. Today the only automated gate is `validate` in
`ci.yml`, which runs typecheck, unit tests and build. Everything else ("does it
actually work in a browser") comes from ad-hoc Playwright scripts under
`~/.local/share/playwright-tools/` and headless-Chrome checks written up in
`docs/plans/*.md`. Those checks catch real bugs. For example,
`docs/plans/mix-accuracy.md` records three browsers giving three different
palettes for the same file. But they live on one machine, they're
hand-written per feature, and they're never re-run.

This proposal moves that local practice into CI in layers. Each layer catches
a class of bug the layer below it can't.

## Layers

| # | Layer | Catches | Blocks merge? | Runs |
|---|---|---|---|---|
| 0 | Unit/integration (exists) | logic, API contracts | yes | every PR |
| 1 | Deterministic Playwright E2E | broken flows, regressions in known paths | yes | every PR, local stack |
| 2 | Visual regression | layout/theme/CSS breakage | yes | every PR |
| 3 | Cross-browser golden data | browser-specific divergence (the mix-accuracy class) | yes | every PR |
| 4 | Agent exploratory QA on the preview | "does the new feature do what the PR says", things nobody wrote a test for | yes (structured verdict) | PRs from `feat/**` after preview deploys |
| 5 | Post-deploy smoke + nightly | deploy/config/infra breakage in production | alerts, auto-revert later | after `main` deploy, nightly |
| 6 | Test-quality meter | tests that pass but assert nothing | report only | weekly |

Layers 1–3 are deterministic, cheap and boring. **Layer 4 is the part that
replaces the human.** Layers 1–3 keep it honest: anything the agent
verifies gets turned into a layer-1 test, so we never pay for an agent to check
the same thing twice.

### Layer 1: deterministic Playwright E2E

- New workspace `e2e/` (`@muralist/e2e`) with `@playwright/test`. This is
  separate from `apps/web` so the web app's deps stay clean.
- **Stack under test, inside CI:** the static export served from
  `apps/web/out`, plus the real API (`apps/api`) on `mongodb-memory-server`
  (the API tests already use `MongoMemoryReplSet`). CORS is already
  env-configured to the web origin, so localhost is set via env. **No code
  widening.**
- **Fixtures:** `docs/example_art/*` (already in repo). Specs port the existing
  scripts:
  - upload → palette renders (`.palette-grid`, `.swatch-card` count in range)
  - merge / auto-combine / per-color disable / lock
  - wall dimensions → estimate numbers
  - maquette PDF download → parsed with `pdf-lib`: page count, colors listed
  - crop-to-wall-ratio, transparent background, reset palette
  - theme toggle respects OS preference and saved choice
  - guest mode: nothing persists, write endpoints return 401/403
  - signed-in: create/rename/trash/restore project, tier limit (`free=3`) →
    `atLimit` UI, locked-not-deleted on over-limit
- **Fail on any `pageerror` or `console.error`.** The current scripts only log these.
- Traces, videos and screenshots are uploaded as artifacts on failure.

**⚠ Flag (AGENTS.md: auth boundary / new endpoint).** Signed-in flows can't
drive real Google/Apple/Facebook/Adobe OAuth headlessly. We need a test-only
way to get a session. Proposal: a Better Auth test provider registered **only**
when `MURALIST_E2E=1`. Startup **refuses** to boot if that is set together
with `NODE_ENV=production`, and a unit test asserts the route 404s in a
production config. This needs your explicit sign-off before it's built.

### Layer 2: visual regression

- Playwright `toHaveScreenshot()` on key screens × {light, dark} ×
  {desktop 1440, phone 390}.
- Baselines are committed under `e2e/__screenshots__/`, and generated in the CI
  container (not locally) so font rendering matches.
- Mask non-deterministic regions (timestamps, project IDs).
- Intended visual changes: the PR updates the baselines. Layer 4's agent
  checks that the diff images match the PR's stated intent, so a human doesn't
  have to eyeball them.

### Layer 3: cross-browser golden data

- For each `docs/example_art/*` file, pin the expected palette from
  `apps/web/scripts/analyze-file.ts` (the Node reference path) in a JSON fixture.
- Run the upload spec on **chromium, firefox and webkit** and assert the
  in-browser palette equals the Node palette. This is the exact bug class from
  `mix-accuracy.md`, which no human reviewer would have noticed.
- The fixture is regenerated by a script. Any change to it shows up in the PR
  diff and is checked by layer 4.

### Layer 4: agent exploratory QA (the "driven web session")

This is what we've been doing locally, run by CI instead of by me in this
terminal.

**Trigger:** the `web-preview.yml` deploy succeeds for a `feat/**` branch
that has an open PR. Runs on a new `workflow_run` workflow
`agent-qa.yml`.

**Runner:** `anthropics/claude-code-action` (or headless `claude -p`) with the
Playwright MCP server and Chromium. Secret: `ANTHROPIC_API_KEY`.

**Input to the agent:**
1. PR title and body, especially the **test plan** section AGENTS.md already
   requires.
2. The PR diff and the linked `docs/plans/<slug>.md`.
3. Preview URL `https://leeroywking.github.io/muralist/previews/<slug>/`.
4. Fixtures in `docs/example_art/`.
5. A repo skill `.agents/skills/qa-preview/` with the rules: what to try,
   what counts as evidence, the output schema.

**What it does:**
1. Executes every step of the PR's test plan in the live preview.
2. Explores beyond it: edge inputs (0/huge wall sizes, tiny/huge/transparent
   images, rapid clicks, back button, reload mid-flow, phone viewport, dark
   mode). This is bounded by a step and time budget.
3. Reviews the layer-2 visual diffs against the PR's stated intent.
4. **Writes new Playwright specs** for every behavior it verified and pushes
   them to the branch as a separate commit. Those then run in layers 1–3
   forever. This is how agent work becomes cheap deterministic coverage.
5. Emits a structured verdict (JSON): each acceptance criterion →
   pass/fail/blocked, with a screenshot path and the exact steps. Also lists
   unexpected findings.

**Second agent (verifier):** a separate run with *no* access to the first
agent's reasoning, only its evidence (screenshots, steps, verdict JSON). It
checks that each "pass" is actually supported by the evidence. One agent
saying "looks good" is not the confidence bar. An independently checked
evidence trail is.

**Output:** a PR comment with the verdict table and embedded screenshots, plus
a check run `agent-qa` that's required by the main ruleset.

**Guardrails:**
- Never runs on fork PRs (public repo). It uses `workflow_run` from same-repo
  `feat/**` branches only, never `pull_request_target` with checkout of PR code.
- The agent's token can push to the PR branch and comment. It can't merge,
  touch `.github/**`, or edit existing tests (it only adds new ones). This is
  enforced by a post-step diff check.
- Page content is untrusted. The skill tells the agent that text on the
  page is data, not instructions.
- Cost cap: max turns/time per run, and it skips when the diff touches no
  `apps/web`/`packages/*` code.

**Backend-only PRs:** the same agent runs against the local CI stack
(layer 1's API + memory Mongo) using `curl` instead of the preview. Previews
are guest-only today because `web-preview.yml` doesn't set
`NEXT_PUBLIC_API_BASE_URL`.

### Layer 5: production smoke

- After a `main` deploy (DO `deploy_on_push`) and nightly: a read-only
  Playwright smoke run against `https://muraliste.com` and
  `https://api.muraliste.com/health`. It uploads `FlowerRepeat.jpg` and asserts
  the known palette from `mix-accuracy.md`.
- On failure it opens an issue (and later, optionally, triggers a DO rollback to the
  previous deployment).

### Layer 6: test-quality meter

- Stryker mutation testing on `packages/core` (pure, fast) weekly. Mutation
  score tells us whether the unit tests actually pin behavior.
- `fast-check` property tests for paint math (coverage ≥ 0, merge is
  order-independent, liters monotonic in wall area).

## What "no human review" means after this

A PR is auto-mergeable when `validate`, `e2e` (layers 1–3) and `agent-qa`
(with the verifier agreeing) are all green. Humans still own:
- product decisions (whether we want the feature at all),
- framework/major dependency bumps (already excluded from auto-merge),
- anything that trips an AGENTS.md "Flag before implementing" rule. The agent
  marks these as `blocked: needs-human` instead of passing them.

## Phasing

1. **Layer 1 + 3 on chromium** (local stack, guest flows only). Port the three
   existing scripts. Make `e2e` a required check.
2. **Test-auth seam** (needs sign-off, see flag above), then signed-in flows.
3. **Layer 2** visual baselines; add firefox and webkit to layer 3.
4. **Layer 4** agent QA: the `qa-preview` skill first, run manually via
   `workflow_dispatch` for a few PRs to tune it, then make it required.
5. **Layer 5** prod smoke; **layer 6** when the above is stable.
